## 项目依赖关系

```
Stardust (核心库) ←── Stardust.Extensions (ASP.NET Core扩展)
    ↑
Stardust.Data (数据层) ←── Stardust.Server (服务端API)
                                ↑
                          Stardust.Web (管理界面)
```

各独立工程：
- **StarGateway** → 引用 Stardust (SDK)，通过 API 与 StarServer 交互
- **StarAgent** → 引用 Stardust (SDK)，通过 API 与 StarServer 交互
- **DeployAgent** → 部署代理，通过 API 与 StarServer 交互
- **Stardust.Web.Vue** → Vue 3 前端（基于 Vite），与 Cube 共存，提供现代化管理界面

## 关键决策（跨模块）

| 决策 | 选择 | 说明 |
|------|------|------|
| 数据采集模式 | 客户端采样+统计，服务端汇总 | 降低 90%+ 网络传输和存储成本 |
| 统计计算 | 流式（5秒）+批计算（30秒）+巡检（600秒）分层 | 热门实时、非热门降载；告警读内存；最终一致性 |
| 部署模式 | Standard/Shadow/Hosted/Task | 适应不同应用场景 |
| 数据清理 | Truncate/Delete 双模式 | 灵活适配数据库权限 |
| 通信协议 | HTTP + WebSocket 双通道 | 心跳/API 走 HTTP，命令走 WebSocket |
| 客户端接入 | AddStardust/UseStardust 一行代码接入 | 零改造集成
| 本机 RPC 认证 | 本机共享令牌（`local.token`），`Info` 匿名 | 来源地址判定挡不住同机低权限进程，而 StarAgent 以 root/SYSTEM 运行。代理启动生成随机令牌写入自身目录（Linux 0600、Windows 仅 SYSTEM/管理员/当前用户），并复制到系统共享位置；`GetServices`/`StartService`/`StopService`/`RestartService`/`SetServer` 常量时间校验，CLI 与 StarGateway 同步携带。局域网广播发现与健康探测只用 `Info`，不受影响。**兼容性**：旧版本机调用方升级前会收到令牌错误，需与代理同批升级 |
| 在线记录复用 | 宽限期（900 秒）内按 NodeID 沿用上一条在线记录 | 弱网重连的会话标识随进程重启变化，每次新建记录会把在线时长与心跳计数切成多段。宽限期内只刷新会话标识，超期视为真正离线，交由超时清理后重建 |
| 埋点长耗时归类 | `ws`（长连接）与 `block`（阻塞类命令）独立归类并从应用均值排除 | WebSocket 的耗时是连接存活时长，Redis `XREAD`/`BLPOP` 等阻塞命令的耗时是队列等待，二者都不是请求处理耗时；混入应用平均耗时会把基础设施等待误判为应用变慢。历史跟踪项在下次保存时纠正归类，无需数据迁移 |
| 前端埋点链路 | 直报优先 + 应用后端中转可选 | 默认浏览器直报星尘，应用后端不参与，后端故障时前端异常仍可回收；同域需求由网关把 `/stardust/*` 透传到星尘独立 upstream；前端只持 10 分钟 `bw_` 签名令牌（绑定应用+来源），无 App Secret。CSP/广告拦截/企业出网策略下可切换中转：`Trace/ReportRelay` 只接受应用 JWT，强制以令牌主体作为 `AppId` 并保留真实客户端 IP；中转把监控绑到业务后端可用性，作为可控降级而非默认（Issue #17） |
| 调用链访问控制 | 默认登录 + 部署级匿名开关 + 短时分享令牌 | 链路数据含请求参数、异常堆栈与客户端 IP，traceId 会随日志和工单外溢，不能当作秘密；`TraceAnonymous` 仅用于内网/演示部署，对外分享改用 HMAC 签名令牌（默认 24 小时，`TraceShareExpire<=0` 为长期），只绑定单个 traceId 且只读；无状态令牌不支持单条撤销，轮换 `TraceShareSecret` 即让全部分享链接失效 |
| 应用重注册默认策略 | 全局默认 + 应用默认跟随（0） | 安全加固 V-1 禁止已存在应用用错误/空密钥动态复用身份后，逐个应用配置维护成本高且容易漏配。新增 `ReRegisterModes.Default=0`（默认），应用跟随 `StarServerSetting.ReRegister`（初始取值开放），可在应用里显式覆盖。模式按从宽到严排列：`Default=0`、`Open=1`、`Trusted=2`、`Temporary=3`、`Off=4`，便于用户按“越往后越严格”理解。**取值兼容**：0 在历史版本表示关闭，现直接解释为默认，存量应用无需数据迁移；历史显式配置过 1/2/3 的应用（仅演示环境少量）升级后按新名称重新选择一次。全局开放意味着知道应用代码的客户端可自助领取密钥，对外部署应按环境收紧为可信接入、临时放行或关闭 |
| 客户端时钟模型 | 单一时间源（`GetNow()`），接入即接管 `Runtime.UtcNow`，不落盘、不改系统时钟 | `Runtime.UtcNow` 走 `TimerScheduler.GlobalTimeProvider`，星尘在客户端 `OnInit` 装上基于 `Span` 的 `ServerTimeProvider`，于是业务与鉴权盐值（基类 `SaltPasswordProvider` 也取 `Runtime.UtcNow`）共用同一个时间源，本机时钟不准也不影响。对齐是**必选项**，客户端不提供开关。`Span` 由登录与每次心跳的 `ServerTime` 刷新。首次登录前用匿名 `/api` 引导（最多等 1 秒，超时不取消请求、结果复用）；登录失败的错误信封也带 `serverTime`，校准后由重试自然恢复。**不持久化**时间差：时钟失准的典型原因是重启后时钟回到旧值，旧差值对应的是另一个时钟，套用只会更糟；正常机器差值≈0，保存无收益。**不自动改系统时钟**：服务端 `SyncTime` 只决定是否修改系统时钟，改完立即重算 `Span`。**定时任务**：相对周期定时器按单调嘀嗒计时不受影响，按日历调度的逻辑会一次性跳变（写日志留痕） |
| 审计历史与命令存储 | 历史备注写入前脱敏；注册通知合并；命令表 30 天保留期 | 节点/应用历史会保存登录请求 JSON，其中 `Secret` 字段不得进入审计库与页面，由 `HistorySanitizer` 在三个历史 Create 入口统一掩码。服务注册通知按“应用+命令+服务名”合并到未完成命令，避免 `registry/register` 随服务变更线性膨胀；`AppCommand`/`NodeCommand` 按 `UpdateTime` 保留 30 天，列表默认隐藏注册通知，显式按命令筛选仍可查看。历史操作名统一保存英文规范键，旧数据不做归一化兼容（历史表定期清理），避免写入进程语言造成同一操作多种文本 |
| 应用类型与采集策略 | `AppKind`（Unknown/Server/Web/Desktop/Mobile/Frontend） | 应用类型只提供默认值，新建应用或类型变化时写入 `Period`/`AlarmOnOffline`/`AutoActive`/`Singleton` 字段，之后由管理员在应用管理里直接调整：Desktop/Mobile/Frontend 心跳 300 秒、关下线告警、埋点不带性能（Desktop/Mobile 默认单例，Browser 不单例）；Server（服务端）与 Web（Web 服务端）60 秒、开告警、不单例，两者默认策略相同，Web 仅用于标记浏览器直接访问的 Web 应用后端。节点代理（StarAgent）按 Server 登记，平台按应用代码识别后套用代理默认值（300 秒、关告警、不自动激活、单例、不带性能、下发平台语言），不再单列类型。`Unknown` 和 `Period=0/60` 表示按类型生成周期；类型变化时仍等于旧类型默认值的项切换到新类型默认值，管理员调整过的值保留，因此不再需要额外的覆盖字段。心跳性能始终采集，`AppTracer.EnableMeter` 只控制埋点上报是否携带性能；`AppOnline` 保存每实例最新快照，`AppMeter` 历史按在线规模做稳定哈希采样（目标 1000 实例）。类型来源为客户端首次注册或 `Kind` 未知时的登录声明，管理员设置后客户端上传不再改变，不做 GUI 推断；语言下发也按类型区分，Desktop/Mobile/Frontend 不下发，Web 按服务端下发；枚举标签以中文为源文，英文译文登记在 `Stardust/Locales/en.yml` 的元数据键 |

**应用类型声明**：客户端在 `StarOptions.Kind` 声明（如 `AddStardust(new StarOptions { AppId = "XCoder", Kind = AppKinds.Desktop })` 或 `new StarFactory(new StarOptions { Kind = AppKinds.Server, ... })`），首次注册时写入 `Kind`；`Server` 是无本地界面的通用服务端，`Web` 表示浏览器直接访问的 Web 应用后端（ASP.NET Core/Node/Java Web），`Desktop` 是 WinForms/WPF/Avalonia 等桌面应用，`Mobile` 是移动应用，`Frontend` 表示浏览器/移动端 WebView 的 JS/TS 前端，发布中心发布其静态包。节点代理（StarAgent）以 `Server` 登记，平台按应用代码识别后按代理策略处理，不再单列类型。管理员在应用管理页设置的 `Kind` 为最终值：`Kind` 未知时客户端登录才更新为上报类型，已设置后客户端上传不再影响服务端。

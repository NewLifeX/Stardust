设计原则

四层看板共用同一套骨架与语义色，差异只在「回答什么问题」

分层下钻

系统 → 项目 → 应用 / 节点，每层只保留上一层的入口与本层结论，点击卡片自然下钻，不迷路。

一屏一主张

顶部 KPI 先给结论，主图解释原因，右侧事件流提示变化。3 秒内能回答「现在好不好、哪里最差」。

状态先行

在线绿 / 告警黄 / 离线红三态贯穿所有卡片与图表；异常优先出现在右上角与事件流，不藏在二级页。

权限即范围

每个看板都标注可见项目范围；无授权时不留空图表，而是给出申请入口。服务端按项目成员过滤，前端只做呈现。

设计令牌

与 Stardust.Web.Vue/src/design-system/tokens.css 同源；色块随明暗主题切换，原型禁止硬编码色值

品牌蓝 渐变紫 星尘青 在线绿 告警黄 离线红 页面底色 卡片表面

说明

设计稿与现有文档、旧稿及实现目标的关系

实现目标：StarWeb（Stardust.Web.Vue，Vue 3 + Element Plus + ECharts + Tailwind）。MVC 控制台（Stardust.Web）不再新增看板功能，本目录仅作为设计蓝本。

与旧稿的关系：Doc/Design/ 下是早期 Bootstrap 浅色示意稿（查看），与真实 StarWeb 视觉不一致；本目录以暗色星尘设计系统为准，后续实现以这里为准。

数据与权限：页面中的数字均为演示假数据，但字段与现有 WebApi 一一对应；权限遵循「服务端按 ProjectUser 注入可见项目范围、前端只呈现」，详见 README。

文件：assets/tokens.css（设计令牌 · 明暗双主题）、assets/dashboard.css（骨架与组件）、assets/theme.js（主题三态与跟随系统）、assets/mock.js（统一假数据与三态）、assets/charts.js（ECharts 双调色板封装）。

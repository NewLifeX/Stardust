# 星尘看板设计稿

> 版本：v1.1 · 2026-10-30（新增明暗双主题，默认跟随系统）
> 实现目标：[StarWeb](../../Stardust.Web.Vue)（Vue 3 + Element Plus + ECharts + Tailwind）
> 视觉基准：[设计令牌](../../Stardust.Web.Vue/src/design-system/tokens.css) · 星尘设计系统（明暗双主题，默认跟随系统）

本目录是星尘平台**分层看板**的设计蓝本，包含 5 个可交互 HTML 原型与本文档。MVC 控制台（`Stardust.Web`）不再新增看板功能，后续实现统一在 StarWeb 完成。

---

## 1. 目标与范围

### 1.1 要解决的问题

现有 StarWeb 只有一个「控制台概览」聚合页，缺少分层视角：

- 进入某个应用时，看不到该应用的在线状态、错误、慢端点、实例健康与最近变更；
- 进入某个项目时，应用与节点分散在不同列表页，无法一屏判断项目健康；
- 运维排查节点问题时，需要同时看资源时序、网络质量、进程与部署情况；
- 平台管理员缺少全局视角，且现有列表接口没有数据级项目隔离。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 分层回答 | 系统 → 项目 → 应用 / 节点，每一层只回答该层最关心的问题 |
| 3 秒结论 | 顶部 KPI 先给结论，主图解释原因，右侧事件流提示变化 |
| 状态先行 | 在线 / 告警 / 离线三态贯穿所有卡片、图表与列表 |
| 权限即范围 | 每页标注可见项目范围；无授权不留空图表，给出申请入口 |
| 可直接落地 | 所有视觉值来自 `--sd-*` 令牌，组件与 StarWeb 现有 GlassCard / KpiStat 对齐 |

### 1.3 非目标

- 不修改 `Stardust.Web`（MVC 控制台）任何功能；
- 不在本目录实现真实数据接入；
- 不定义新的后端协议细节（仅给出 scope 契约建议，见 §7.2）。

## 2. 设计总览

### 2.1 四层信息架构

| 层级 | 看板 | 入口 | 回答的问题 | 主要下钻 |
|:----:|------|------|------------|---------|
| L0 | 系统级看板 | 侧栏「系统」 | 平台整体好不好？哪个项目/应用最差？ | 项目看板、应用看板 |
| L1 | 项目看板 | 系统看板项目行 / 项目列表 | 这个项目下的应用和节点现在怎么样？ | 应用看板、节点看板 |
| L2 | 应用看板 | 项目应用卡 / 应用列表 | 应用是否在线？有没有报错？慢在哪？实例健康吗？ | 节点看板、调用链、跟踪统计 |
| L2 | 节点看板 | 项目节点行 / 实例表 | 这台机器健康吗？谁在吃资源？最近做过什么？ | 应用看板、指令记录 |
| — | 大屏模式 | 系统看板「投屏」 | 无人值守时，一屏轮播全局态势 | — |

### 2.2 统一骨架

```
┌────────────────────────────────────────────────────────────────────────┐
│ 顶栏：品牌 · 项目上下文 · 可见范围徽标 · 时钟 / 刷新 / 账号              │
├────────────────────────────────────────────────────────────────────────┤
│ 作用域栏：面包屑 · 页面标题 / 状态 · 时间范围 · 自动刷新 · 投屏 · 主操作 │
├────────────────────────────────────────────────────────────────────────┤
│ KPI 条（6 卡）：结论数字 + 环比 + 迷你趋势                               │
├───────────────────────────────────────────────┬────────────────────────┤
│ 主区：趋势 / 矩阵 / 列表（24 栅格，14px gutter）│ 事件栏（可折叠）        │
├───────────────────────────────────────────────┴────────────────────────┤
│ 页脚：数据来源 · 最后更新时间 · 下钻提示                                 │
└────────────────────────────────────────────────────────────────────────┘
```

- 侧栏沿用 StarWeb 56px 图标导航（原型中为 60px，实现时以现有布局为准）。
- 卡片统一为玻璃拟态：`backdrop-filter: blur(14px)` + 1px 边框 + 16px 圆角 + 蓝调阴影。
- 页面宽度上限 1680px，超宽屏留白，避免大屏拉伸导致信息密度过低。

### 2.3 栅格与断点

| 断点 | 主区栅格 | KPI | 说明 |
|------|----------|-----|------|
| ≥ 1360px | 24 列 | 6 列 | 完整双栏 + 事件栏 |
| 1100–1359px | 12 列 | 3 列 | 卡片两两合并，事件栏移至底部 |
| < 1100px | 2 列 | 2 列 | 单列滚动，保留 KPI 与主图 |
| < 720px | 1 列 | 1 列 | 移动端仅保证可读 |

## 3. 设计语言

### 3.1 色彩

| 令牌 | 暗色 | 浅色 | 用途 |
|------|------|------|------|
| `--sd-color-brand` | `#6673FF` | `#4F5BE8` | 主操作、活动态、品牌 |
| `--sd-color-brand-2` | `#8C5CF5` | `#7A46E0` | 渐变末端、应用拓扑节点 |
| `--sd-color-accent` | `#6FE3EC` | `#0E8F9B` | 强调、焦点、星尘青 |
| `--sd-color-online` | `#43E8A3` | `#0B9A66` | 在线 / 成功 / 正常 |
| `--sd-color-alert` | `#FFC208` | `#B45309` | 告警 / 接近阈值 |
| `--sd-color-offline` | `#FF4545` | `#D92D20` | 离线 / 错误 / 超限 |
| `--sd-bg-page` | `#16202A` | `#F2F5FA` | 页面底色 |
| `--sd-bg-surface` | `#1F2A33` | `#FFFFFF` | 卡片 / 侧栏表面 |
| `--sd-bg-elevated` | `#26333F` | `#FFFFFF` | 悬浮层 / 抽屉 |
| `--sd-text-primary` | `#E6EDF3` | `#16202A` | 主文本 |
| `--sd-text-secondary` | `#8A97A6` | `#5C6B7A` | 次要文本 |

- 原型与实现都只能引用变量，禁止在页面内硬编码十六进制色值；
- 浅色令牌是本次设计稿的扩展（官方 `tokens.css` 目前只有暗色），实现时建议把 `[data-theme="light"]` 块合并回上游，保持单一事实源；
- 图表（canvas）无法读取 CSS 变量，`assets/charts.js` 维护 **暗色 / 浅色双调色板**，按 `<html data-theme>` 选择；主题切换后需重建图表（原型用重载，见 §15）。

### 3.2 字体与数字

- 正文：`Inter / PingFang SC / Microsoft YaHei`，正文 14px、辅助 11–12px；
- 数字：`font-variant-numeric: tabular-nums`，KPI 29–30px，大屏 `clamp(24px, 2.35vw, 44px)`；
- 代码 / 标识：`JetBrains Mono / Consolas`，用于 IP、AppId、traceId、版本号。

### 3.3 卡片与状态

- 卡片头：3px 品牌渐变竖条 + 13px 半粗标题 + 右侧提示 / 链接；
- 状态药丸：色值 12% 透明度底 + 6px 圆点，在线状态加呼吸动画；
- 水位条：正常绿 / 警戒黄（≥65%）/ 危险红（≥80%），项目节点资源统一使用；
- 空态：图标 + 一句原因 + 下一步操作，不出现空白图表。

## 7. 权限与数据范围

### 7.1 现状（必须正视）

《[架构审查与权限分析](../架构审查与权限分析.md)》第五节结论：当前只有**功能级权限**（`[EntityAuthorize]`），**没有数据级 `[DataPermission]`**；`ProjectUser`（项目成员）表未被任何业务查询使用；约 77% 的明细与时序表没有 `ProjectId`，只能经 `AppId` / `NodeId` 间接关联；Vue 前台没有项目作用域概念。

因此看板不能只在界面上"藏数据"——必须在服务端按当前用户可见项目过滤，否则受限账号仍可通过接口看到全量数据。

### 7.2 建议的 scope 契约

```http
GET /api/dashboard/scope
{
  "userId": 1024,
  "isAdmin": false,
  "projectIds": [1, 2, 3],
  "totalProjects": 12,
  "visibleProjects": 3,
  "generatedAt": "2026-10-30T14:20:00+08:00"
}
```

- 所有看板接口（或统一的查询过滤器）接收/注入 `projectIds`：
  - 有 `ProjectId` 的表：直接 `ProjectId IN (...)`；
  - 无 `ProjectId` 的表：通过 `AppId` / `NodeId` 子查询间接过滤；
- 管理员（`isAdmin`）返回全部项目，前端仍显示「全部 12 个项目」；
- 前端在 Pinia 保存 scope，所有请求自动携带；URL 中的 `projectId` 只作为筛选，不作为权限依据；
- 下钻详情（应用、节点）必须先校验所属项目在 scope 内，否则返回 403 并跳转无权限页；
- 大屏与导出接口同样应用 scope，不能因为是"只读"而绕过。

### 7.3 三态设计

| 状态 | 触发 | 表现 |
|------|------|------|
| 全量 | 管理员 / 全部项目可见 | 徽标「全部 12 个项目」，正常展示 |
| 受限 | 仅部分项目可见 | 徽标「可见 3 / 12 个项目」+ 黄色提示条；隐藏未授权项目行；KPI 只统计可见范围 |
| 无授权 | 未加入任何项目 | 整页空态，说明原因并给出申请入口；不渲染任何图表 |

评审时可通过 `?scope=limited` / `?scope=none` 直接查看后两态。

## 8. 交互规范

1. **时间范围**：`1 小时 / 24 小时 / 7 天` 分段控件；切换只影响趋势图与 Top 列表，不刷新整页。
2. **自动刷新**：30s（实时指标）/ 60s（统计）/ 5min（元数据）；页面失焦时暂停，按钮显示倒计时。
3. **下钻**：卡片、表格行、拓扑节点均可点击；下钻路径写入 URL（`/stardust/dashboard/app/:id?projectId=2&range=24h`），支持分享与浏览器后退。
4. **空态**：
   - 无数据：说明原因 + 接入引导（SDK 代码块）；
   - 无权限：申请入口；
   - 加载失败：错误摘要 + 重试按钮；
   - 首屏：骨架屏，刷新时保留旧数据 + 按钮转圈（沿用现有概览页做法）。
5. **大屏**：空格暂停/继续轮播；点击指示条切换视角；`Esc` 退出全屏。

## 9. 响应式与性能

- 图表统一使用 `EChart.vue` 封装，`resize` 由容器 ResizeObserver 触发；
- 24h 曲线按 1 分钟粒度最多 1440 点，前端降采样到 200–300 点绘制；
- 首屏并行请求：scope、项目、应用、节点、聚合统计；
- 拓扑图节点超过 200 个时改为按项目聚合，避免力导向卡顿；
- 大屏隐藏侧栏与顶栏，减少一层布局计算；`prefers-reduced-motion` 下关闭轮播与呼吸动画。

## 15. 明暗主题与「跟随系统」

### 15.1 三态与默认值

| 模式 | 值 | 行为 |
|------|----|------|
| 跟随系统 | `auto`（默认） | 读取 `prefers-color-scheme`，系统切换时自动跟随 |
| 浅色 | `light` | 锁定浅色 |
| 深色 | `dark` | 锁定深色 |

- 选择写入 `localStorage['sd-theme']`；
- 落地在 `<html data-theme="light|dark" data-theme-mode="auto|light|dark">`；
- 首屏在 `<head>` 内联脚本中先行应用，避免闪白/闪黑；
- 切换控件为三枚图标（显示器 / 太阳 / 月亮），系统看板在顶栏右侧，大屏在标题右侧，总览页在右上角。

### 15.2 浅色主题设计要点

- 页面底色改为冷灰蓝 `#F2F5FA`，卡片纯白 + 更浅的灰蓝阴影，去掉暗色辉光；
- 星点背景降为淡紫蓝细点，保留「星尘」气质但不抢内容；
- 语义色整体加深（在线 `#0B9A66`、告警 `#B45309`、离线 `#D92D20`），保证白底对比度；
- 大屏保持同样的信息层次：数字不再发光，改为深色高对比数字 + 细边框卡片；
- 顶栏、侧栏、表格、空态、状态药丸全部通过同名变量自动适配，页面无需写两套样式。

### 15.3 StarWeb 实现建议

1. 现在 `src/main.ts` 强制 `document.documentElement.classList.add('dark')`，需移除并改为主题 store；
2. Element Plus 的暗色依赖 `html.dark`，建议同时维护 `data-theme`（业务令牌）与 `dark` class（Element），二者由同一状态驱动；
3. `auto` 模式监听 `window.matchMedia('(prefers-color-scheme: dark)')`，系统变化时只更新状态、不刷新页面；
4. ECharts 使用双调色板：监听主题变化后 `setOption` 重绘（不要像原型一样 reload）；小屏/大屏图表共用同一套主题函数；
5. 大屏默认「跟随系统」，值守时可锁定深色；切换入口放在大屏头部，避免投屏时误触；
6. 测试补充：三模式切换、系统主题变化、`localStorage` 持久化、图表颜色随主题重绘、浅色下对比度（WCAG AA）。
